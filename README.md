# Автотесты для тестового задания

Тесты для Spring Boot приложения из задания (internal-0.0.1-SNAPSHOT.jar). Проверяются вход, действие и выход пользователя, API ключ, формат токена и действия, а также то, как приложение ведет себя, когда внешний сервис отвечает ошибкой.

Стек: Java 17, JUnit 5, WireMock, Allure, Maven.

## Как запустить

Нужны Java 17 и Maven. Файл internal-0.0.1-SNAPSHOT.jar надо положить в папку app (в репозитории его нет, он из архива с заданием). Если лежит в другом месте, путь можно передать так: `-Dapp.jar=путь/к/файлу.jar`.

Порты 8080 и 8888 должны быть свободны. Приложение и заглушку внешнего сервиса вручную запускать не надо, тесты поднимают их сами.

```
mvn clean test
```

Отчет Allure:

```
mvn allure:serve
```

Лог приложения после прогона лежит в target/app.log.

## Что нашлось

Четыре теста падают специально, они описывают баги. В названии у них написано ДЕФЕКТ.

- Токен из букв G-Z не принимается, хотя в документации разрешено A-Z. Работают только 0-9 и A-F.
- GET запрос на /endpoint отвечает 500, а должен 405.
- Запрос с JSON вместо формы отвечает 500, а должна быть ошибка клиента (415 или 400).
- Запрос на несуществующий адрес отвечает 500, а должен 404.

Чтобы запустить без этих четырех: `mvn test -DexcludedGroups=defect`

## Что не считала багом

- Любая ошибка внешнего сервиса превращается в ответ 500. В документации не написано, какой код должен быть, поэтому тесты проверяют только, что пришла ошибка и сессия не создалась.
- Пробелы по краям action приложение обрезает само.
- Если /doAction вернул ошибку, сессия остается, следующий ACTION работает.
